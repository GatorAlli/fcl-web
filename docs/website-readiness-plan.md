# Felix Controls website readiness plan

This plan covers the 15 checklist items visible in the screenshots. The site stays on Next.js static export, GitHub Actions, and the existing cPanel deployment. The snippets are implementation examples for review.

## Decisions

| Area        | Agreed behavior                                                                                           |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| Consent     | One worldwide opt-in. Load Google Analytics 4 and Cloudflare Web Analytics only after acceptance.         |
| Measurement | Use GA4 for page views and enquiry intent. Use Cloudflare Web Analytics for traffic and page performance. |
| Enquiry     | Keep local validation, review, copy, and email-draft handoff. Report clicks as intent.                    |
| Release     | Build on GitHub Actions, then publish the matching commit with cPanel’s two existing buttons.             |

## 1. Confirm the baseline and enforce HTTPS

- Audit the current HTTP and HTTPS behavior of `felixbd.com` and `www.felixbd.com`. Check a deep link with a query string, certificate coverage, redirect count, and mixed content. Confirm the Cloudflare proxy and TLS mode before choosing where to enforce redirects.
- If Cloudflare proxies the website, use an edge HTTPS redirect scoped to the website hostnames and verify Full (strict) can validate the origin. If the site is served directly, configure the redirect in cPanel or the `.htaccess` generated by `scripts/deploy-cpanel.sh`. Keep one redirect owner. [Cloudflare HTTPS documentation](https://developers.cloudflare.com/ssl/edge-certificates/additional-options/always-use-https/)
- Review tracked configuration and the public build archive for credentials, private files, source-only materials, and unintended environment values. Build scanning should report filenames or redacted findings. Public analytics identifiers can be injected at build time. Keep API keys, service tokens, and private credentials outside the static export. [Next.js environment variables](https://nextjs.org/docs/app/guides/environment-variables)

## 3. Implement consent and analytics

1. Add a small client-side consent provider under `app/layout.tsx`. Keep the initial state undecided until the browser reads a versioned preference. Give **Accept analytics** and **Reject analytics** equal prominence. Keyboard users must be able to dismiss the notice by choosing either action and reopen it from the footer.
2. Save acceptance or rejection in first-party storage. If storage is unavailable, honor the choice for the current page and use undecided on the next load. On withdrawal, persist the rejection, disable GA collection for the current page, and reload into the blocked state. Check network activity through the transition, including Cloudflare’s page teardown. Cover removal of the site’s scoped GA cookies where applicable.
3. Verify access to the Felix GA4 web stream and Cloudflare Web Analytics site. Set up Cloudflare for **manual** beacon loading and disable automatic injection for the same host. Load its beacon once after consent and keep its built-in client-side navigation measurement. In GA4, use basic consent mode with advertising consent denied. Turn off enhanced measurement that would duplicate the chosen clicks or navigation events, including browser-history page views, outbound clicks, form interactions, and file downloads. [Cloudflare manual setup](https://developers.cloudflare.com/web-analytics/get-started/) · [Cloudflare SPA measurement](https://developers.cloudflare.com/web-analytics/get-started/web-analytics-spa/) · [Google consent mode](https://developers.google.com/tag-platform/security/concepts/consent-mode) · [GA4 manual page views](https://developers.google.com/analytics/devguides/collection/ga4/views)

Add repository variables to the existing **Build static website** step in `.github/workflows/cpanel-build.yml`. These values identify browser tags and will appear in the build. Keep production analytics off on development and preview hosts.

```yaml
env:
  NEXT_PUBLIC_GA4_MEASUREMENT_ID: ${{ vars.GA4_MEASUREMENT_ID }}
  NEXT_PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN: ${{ vars.CLOUDFLARE_WEB_ANALYTICS_TOKEN }}
```

In the analytics client component, use `usePathname()` and a ref for the previous page URL. The proposed `loadScriptOnce` helper sets attributes before appending the element. The `prepareGa4Once` helper queues default denial, an update granting only `analytics_storage`, and `config` with `send_page_view: false` before loading the Google script.

```tsx
useEffect(() => {
  if (consent !== "accepted" || window.location.hostname !== "felixbd.com") {
    return;
  }

  if (cloudflareToken) {
    loadScriptOnce(
      "cloudflare-web-analytics",
      "https://static.cloudflareinsights.com/beacon.min.js",
      {
        type: "module",
        "data-cf-beacon": JSON.stringify({ token: cloudflareToken }),
      },
    );
  }

  if (!gaId || !pathname) return;

  const pageUrl = new URL(pathname, window.location.origin).href;
  if (pageUrl === previousPage.current) return;

  const context = {
    page_location: pageUrl,
    page_referrer:
      previousPage.current ??
      (document.referrer ? new URL(document.referrer).origin : ""),
  };
  const gtag = prepareGa4Once(gaId, context);
  gtag("set", context);
  gtag("event", "page_view", { ...context, page_title: document.title });
  previousPage.current = pageUrl;
}, [consent, pathname]);
```

Queue the following commands inside `prepareGa4Once` before inserting `gtag.js`. The route context supplies the sanitized page URL and referrer on the first load.

```ts
gtag("consent", "default", {
  analytics_storage: "denied",
  ad_storage: "denied",
  ad_user_data: "denied",
  ad_personalization: "denied",
});
gtag("consent", "update", { analytics_storage: "granted" });
gtag("js", new Date());
gtag("config", gaId, {
  ...context,
  send_page_view: false,
  allow_google_signals: false,
  allow_ad_personalization_signals: false,
});
```

| GA4 event                 | Trigger                                  |
| ------------------------- | ---------------------------------------- |
| `contact_email_click`     | Click a published contact email link.    |
| `contact_phone_click`     | Click a published phone link.            |
| `enquiry_draft_click`     | Click **Open email draft** after review. |
| `brochure_download_click` | Click a company profile download link.   |

Use one consent-aware event helper and attach these names to the relevant links in Contact, the footer, the brochure links, and the enquiry review. The email-draft link fires only `enquiry_draft_click`. Keep query strings, fragments, full link targets, enquiry field values, and message text out of GA4. Review reports as click intent. [Google guidance on personal information](https://support.google.com/analytics/answer/6366371)

```tsx
<a
  className="fcl-button"
  href={email}
  onClick={() => trackAnalyticsEvent("enquiry_draft_click")}
>
  Open email draft
</a>
```

## 5. Improve media, load speed, links, and form validation

- Audit real image usage in the shared `Photo` component, home hero, project and sector pages, logos, and leadership portraits. Describe informative images in context, use `alt=""` for decorative images, and make sure linked logos have an accessible name. [W3C alt-text decision tree](https://www.w3.org/WAI/tutorials/images/decision-tree/)
- Rank images by bytes and rendered size. Start with the largest visible hero and project photographs. Precompress oversized files into suitable WebP variants before committing them because the cPanel export serves images statically. Compare crops at mobile and desktop widths, retain dimensions to prevent layout shift, and keep the primary hero available promptly. [Next.js static exports](https://nextjs.org/docs/app/guides/static-exports)
- Take a mobile Lighthouse baseline on Home, Contact, and one image-heavy detail page. Compare medians from repeated runs after the change. Use field data when available and look for good 75th-percentile Core Web Vitals of LCP ≤ 2.5 s, INP ≤ 200 ms, and CLS ≤ 0.1. [Core Web Vitals thresholds](https://web.dev/articles/vitals)
- Extend `scripts/verify-frontend.mjs` to crawl built routes, internal links, fragments, public assets, and the brochure. Triage manufacturer links separately and confirm the intended replacement before changing a destination. Check legacy high-value URLs against Search Console or an existing URL list and map verified equivalents where needed.
- In `components/site/enquiry-form.tsx`, keep existing name and email checks, the 20-character minimum, field errors, focus management, and review/copy fallback. Trim inputs, validate the selected solution against the known options, and set a message limit after testing draft URLs on supported email clients. Check accented and Bangla characters, optional international numbers, editing after review, and the copy fallback on a phone without a configured mail app.

```ts
const message = values.message.trim();

if (message.length < 20) {

if (!enquiryOptions.some(({ value }) => value === values.solution)) {
```

Wire the solution error to `BrandSelect` with the same accessible feedback pattern used by the other fields. Keep the review copy explicit that the visitor sends the email from their own app.

## Release checks

| Check      | Pass condition                                                                                                                                                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Consent    | Fresh and rejected sessions make no GA4 or Cloudflare analytics requests. Acceptance loads both once. Reload, back/forward, and withdrawal respect the saved choice.                                                                                  |
| Analytics  | GA4 DebugView shows one page view for a measured route change and one event per deliberate click. Cloudflare shows visits and performance data for accepted traffic. Inspect payloads for personal data and raw query strings.                        |
| SEO        | Canonicals, titles, descriptions, and share tags appear on the exported HTML. The share image, icon, sitemap, and robots file return successfully on the live site.                                                                                   |
| Quality    | Run `npm run lint`, the static production build, and the link checker. Test keyboard navigation, mobile layout, form errors, the email draft, and the PDF. Compare performance with the baseline.                                                     |
| Deployment | Confirm the approved policy text and both analytics IDs, wait for GitHub Actions to build the approved commit, then use **Update from Remote** and **Deploy HEAD Commit**. Verify the live site and keep the previous release available for rollback. |
